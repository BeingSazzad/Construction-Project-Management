# GLOBAL UI RULES

Enforce these strict UI design and engineering constraints across all project components and views:

## Core Directives
1. **Never invent requirements**: Only implement what is explicitly asked or required by the core user workflow.
2. **Never add features without explicit product need**: Resist feature creep.
3. **Never use generic SaaS patterns automatically**: Avoid boilerplate cookie-cutter dashboards.
4. **Never add AI UI unless required**: Do not throw AI badges or AI chat boxes where a simple input/button works.
5. **Never fill empty space with cards**: Empty space provides visual breathing room and clarity.
6. **Never make everything a card**: Use typography, subtle dividers, lists, or inline rows instead of boxing everything into cards.
7. **Never add decorative UI without purpose**: Every icon, badge, border, or button must serve a clear function.

## Primary Goal
Build the simplest interface that completely solves the user's actual task.

## Principle of Uncertainty
**When uncertain: REMOVE rather than ADD.**

## Final UI Feel
The final interface must feel:
- **Clean**
- **Modern**
- **Intentional**
- **Production-Ready**
- **Non-Generic**
- **Product-Specific**
